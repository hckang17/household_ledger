# 분석 페이지 준비 상태와 성능 검증

## 적용 범위

기간별 지출 분석의 현재 지출, 전월 비교, 수입 기반 예산과 고정지출을 준비한 뒤 하나의 결과 스냅샷을 표시한다. 여행 분석과 별도의 심층 분석 페이지의 계산 흐름은 변경하지 않는다.

- `prepared_expense_analysis_provider.dart`: 날짜 기반 쿼리로 조회와 집계를 조정한다. 조회를 동시에 시작하고 모든 입력이 도착한 뒤 worker를 호출한다. 로딩·오류를 빈 정상 데이터로 치환하지 않는다.
- `prepare_expense_analysis.dart`: 기존 순수 계산기를 조합하여 네 가지 분류, 일별 추이, 음식 분석, 월말 예상을 한 번 계산한다.
- Android 등 네이티브 플랫폼에서는 `compute`가 별도 isolate에서 계산한다. Web의 `compute`는 같은 이벤트 루프에서 실행되므로 같은 성능 효과를 보장하지 않는다.
- Provider가 결과를 보관하는 동안 차트 터치나 화면 재빌드로 다시 계산하지 않는다. 원본 Provider가 무효화되면 다시 준비하며, 과거 요청의 완료가 새 요청 결과를 덮어쓰지 않는다. 구독이 없어진 요청은 조회 완료 후 새 worker를 시작하지 않는다. 이미 시작한 isolate 작업을 강제 취소하지는 않는다.
- 도넛 선택은 `ValueNotifier`로 차트만 갱신한다. 각 분석 카드의 repaint 경계를 나누고 그래프의 초기 애니메이션을 생략한다.
- 메인 셸은 방문한 탭만 생성하고 유지한다. 다른 탭을 타이머로 생성하는 작업을 없애고 숨겨진 탭의 ticker를 정지한다.

준비 완료는 **조회와 집계의 완료**를 뜻한다. 화면 아래의 모든 픽셀이 GPU에 미리 그려졌다는 의미는 아니다. 무조건 일정 시간을 기다리는 타이머나 가짜 진행률은 사용하지 않는다. 긴 Column의 구조는 고정지출 바로가기와 튜토리얼의 스크롤 타깃을 유지하기 위해 보존했다. 카드가 계속 늘어나면 이 타깃 처리와 함께 sliver 전환을 검토한다.

## 자동 검증

- 계산: 월별 고정지출 포함, 기간 모드 제외, 윤년 월말, 1월, 빈 데이터, 불변 결과.
- Provider: 전월·수입 대기, 결과 재사용, 원본 갱신, 조회 실패와 재시도, 오래된 worker 완료, 실제 isolate 모델 전달.
- Widget: 한·일 로딩·오류·재시도, 좁은 화면과 확대 글꼴, 스크롤, 도넛 선택 시 예측 Widget 재생성 방지.
- 기존 예측 차트 회귀 테스트, 전체 `flutter test`, `flutter analyze`, 한·일 키와 placeholder 일치 검사.

## Android 실기기 후속 확인

실기기가 연결되지 않은 개발 환경에서는 프레임 개선율을 확정할 수 없다. 동일한 기기·데이터로 변경 전후를 비교한다.

1. `flutter run --profile -d <device-id>`로 실행한다. 실제 사용과 동일한 월 및 긴 기간을 각각 선택한다.
2. DevTools Performance에서 첫 진입과 첫 하단 스크롤을 기록하고 UI/raster 프레임 시간을 구분한다. 60Hz 기기 기준 16.7ms, 120Hz 기준 8.3ms 초과 프레임을 비교한다.
3. 월을 빠르게 전환하거나 지출을 수정했을 때 이전 결과가 섞이지 않는지 확인한다.
4. 도넛 선택, 고정지출 바로가기, 튜토리얼, 탭 복귀 시 스크롤 위치를 확인한다.
5. release 빌드에서도 같은 동작을 확인한다. 계산이 짧아졌는데 raster 지연이 남으면 실제로 느린 차트부터 그리기 비용을 줄인다.

금액·메모·이메일 등 사용자 데이터를 성능 로그에 기록하지 않는다. 현재 worker의 debugLabel은 `expense-analysis`이며 입력 내용은 포함하지 않는다.
