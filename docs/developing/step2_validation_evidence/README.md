# 순서 2: 소비기록·팝업 높이 제약 수정

2026-09-16. [후속 지침서](../beta_remediation_and_multidevice_ui_guide.md)의 B01·B09를 수정한다. 순서 1의 기존 변경과 증거는 보존했다.

## 변경 내용

- 소비기록의 여행 컨트롤·달력·날짜별 기록을 하나의 `CustomScrollView`로 구성했다. 기록은 행별 `SliverList`로 지연 생성한다.
- 목록 끝에 96dp 여유 공간을 두어 마지막 기록을 플로팅 기록 버튼 위로 스크롤할 수 있게 했다. 날짜 선택, 선택일 조회, 월 전체 조회, 달력 접기를 유지했다.
- 달력 셀은 실제 글꼴·TextScaler·가용 셀 폭으로 날짜와 금액 줄 높이를 측정한다. 확대된 두 자리 날짜가 줄바꿈되는 경우에도 높이를 확보한다.
- 소비기록 로딩 화면도 높이가 부족하면 스크롤할 수 있게 했다.
- 공통 `BootstrapDialog`의 제목·본문·액션을 함께 스크롤한다. Dialog가 키보드 inset을 처리하며, 남은 높이가 240dp 미만일 때만 팝업의 세로 바깥 여백과 안쪽 여백을 줄인다. 기본 색상·카드 모양·최대 폭·버튼 의미는 유지했다.

## 자동 검사

- 한국어·일본어 × 320×568/640×360/360×640/800×1280 조건. 가로 및 360×640은 글자 배율 1.8을 사용했다.
- 동일 날짜에 기록 40건을 넣어 마지막 기록까지 스크롤, 버튼과 겹치지 않는 위치, 화면 밖 기록의 지연 생성, 달력으로 돌아가 접기를 검사했다.
- 2026년 2월·9월·8월의 4·5·6주 달력에서 마지막 날짜 선택, 조회 콜백, 접은 상태에서 화면 회전과 재펼치기를 검사했다.
- 낮은 화면의 로딩 → 빈 데이터/오류 전환을 검사했다.
- 팝업은 640×360, 글자 1.8, 상단 안전 영역 24dp, 키보드 244dp 조건에서 입력·저장·취소를 검사했다.
- 실제 키보드 검사에서 스크롤만 추가하면 팝업 안쪽 공간이 거의 남지 않는 문제가 드러났다. [여백 보완 전 캡처](android_landscape_keyboard_before_spacing.png)를 남기고, 이를 반영해 세로 여백 정책과 회귀 테스트를 강화했다.

실행 결과는 `checks.txt`에 기록한다. 페이지 검사에서 사용하는 글꼴은 Widget 테스트 환경의 글꼴이며, Android 캡처와 동일한 픽셀 모양을 보장하는 골든 검사는 아니다.

## Android 확인

전용 `ledger_beta_api36`, API 36 에뮬레이터에서 해상도·글자 크기를 변경했다. density 320, 호스트 GPU, Impeller 비활성 조건이다. 개인 기기 데이터는 사용하지 않았다.

- [기존 작은 화면](android_small_before.png) → [수정 후 달력](android_small_after_top.png) → [스크롤한 기록](android_small_after_records.png).
- [360×640dp, 글자 1.8 달력](android_largefont_top.png)과 [기록 목록](android_largefont_records.png).
- 가로 화면에서 실제 Android 키보드를 띄운 뒤 [입력값과 액션 버튼](android_landscape_new_dialog_typed_actions.png)까지 스크롤하고 저장을 눌러 [팝업이 정상 종료된 화면](android_landscape_new_dialog_saved.png)을 확인했다. 같은 이름의 UIAutomator XML도 함께 보관한다.

## 후속 범위

분석 기간 선택부와 영어 요일의 현지화는 순서 3에서 처리한다. 기존 기록 타일의 좁은 폭에서 금액·내용을 말줄임하는 정책, 전체 팝업 외형 통일은 이번 스크롤 수정과 별도다. 실물 기기·다른 키보드 앱은 추가 검증이 필요하다.
