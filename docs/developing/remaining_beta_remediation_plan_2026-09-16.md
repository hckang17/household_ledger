## 3. 작업별 수정 지침

### 3.1 PDF 파일 무결성과 암호 문구

현재 PDF 파일명은 `사용자명_기간.pdf`로 고정되어 같은 조건으로 다시 생성하면 기존 파일을 덮어쓴다. 생성 시각과 짧은 충돌 회피 값을 파일명에 포함하고, 같은 경로가 이미 있으면 새 이름을 다시 계산한다. 최종 파일에 직접 쓰지 말고 같은 디렉터리의 임시 파일에 `flush`까지 성공한 후 이름을 바꾼다. 실패 시 기존 파일과 목록은 그대로여야 한다.

PDF 암호화는 아직 구현하지 않는다. `_passwordCtrl`, 입력란, 암호가 적용된다고 설명하는 한·일 문구와 README 내용을 제거한다. 암호화 미지원 경고만 남기는 방식보다 입력 자체를 없애 사용자가 기능으로 오해하지 않게 한다.

완료 조건:

- 같은 사용자·기간으로 연속 3회 생성해 서로 다른 파일 3개가 보존된다.
- 쓰기 실패를 주입해 기존 파일의 바이트와 수정 시각이 바뀌지 않는다.
- 화면과 README 어디에도 PDF 암호 설정이 가능한 것처럼 보이는 표현이 없다.

### 3.2 사용자가 선택하는 저장 위치

앱 전용 저장소의 생성본은 작업 파일로 유지할 수 있지만 이를 사용자가 선택한 최종 보관 위치라고 표현하지 않는다. 완료창 행동을 다음처럼 구분한다.

- `다른 위치에 저장`: Android Storage Access Framework의 `ACTION_CREATE_DOCUMENT`로 목적지와 파일명을 선택하고 실제 쓰기 성공 후 완료 안내
- `공유`: OS 공유창 실행
- `열기`: PDF처럼 즉시 열 수 있는 형식에만 제공
- `완료`: 창 닫기

현재 의존 중인 Android `file_selector`는 저장 위치 선택 구현을 제공하지 않으므로, 지원되는 플러그인을 최소 범위로 도입하거나 작은 네이티브 채널로 SAF를 연결해야 한다. URI는 일반 파일 경로로 가정하지 말고 `ContentResolver` 스트림으로 기록한다. 취소와 실패는 성공 안내와 분리한다.

완료 조건:

- Android 파일 선택기에서 Downloads 등 사용자가 고른 위치에 CSV와 PDF를 저장한다.
- 저장한 CSV를 ADB 복사 없이 앱에서 다시 선택해 정상 복원한다.
- 취소 시 원본 작업 파일과 기존 사용자 파일이 변하지 않는다.

### 3.3 튜토리얼 임시 데이터 정리

튜토리얼 데이터는 이미 `note == '__tutorial_mock__'` 표식이 있으므로 메모리 ID만 신뢰하지 않는다. 저장소에 표식 조회·삭제 기능을 만들고, 시작 전 잔존 데이터 정리와 정상 종료 정리를 같은 반복 안전한 함수로 처리한다. 사용자 데이터가 같은 설명이나 금액을 가졌다는 이유로 삭제하지 않으며 정확한 전용 표식만 사용한다.

완료 조건:

- 삽입 직후, 화면 이동 중, 앱 강제 종료 후 재실행에서 임시 기록이 모두 정리된다.
- 정리를 여러 번 호출해도 오류나 추가 삭제가 없다.
- 같은 날짜·금액·설명을 가진 일반 사용자 기록은 보존된다.

### 3.4 시스템바와 조작 접근성

상태바·내비게이션바 아이콘 밝기를 단색과 4개 그라데이션의 실제 상단·하단 명도에 맞춰 설정한다. 애니메이션 중 프레임에서도 대비가 유지되어야 하며 페이지별 임의 설정 대신 루트 배경 정책이 결정한다.

수입·고정지출의 이전/다음 달, 고정지출 수정/삭제, 메타데이터 펼치기·추가 등 아이콘 전용 버튼에 현지화된 동작·대상 레이블을 붙인다. 시각 아이콘 크기와 별개로 터치 영역은 최소 48×48dp를 유지한다.

완료 조건:

- 단색과 4개 그라데이션, 일반·여행 모드에서 시스템바 정보를 읽을 수 있다.
- TalkBack 탐색 시 버튼 목적과 수정·삭제 대상이 한·일 언어로 구분된다.
- 320×568dp와 글자 1.8에서도 터치 영역이 겹치거나 잘리지 않는다.

### 3.5 검색 응답성과 팝업 통일

검색 Provider가 결과를 반환하면 1.5초 타이머와 가짜 N/N 애니메이션을 기다리지 않고 결과를 표시한다. 실제 계산이 오래 걸리는 경우에만 진행 상태를 유지하며, 새 검색이 시작되면 이전 결과 콜백을 무효화하는 현재 토큰 보호는 보존한다.

남아 있는 `AlertDialog` 호출을 기능별로 조사해 공통 `BootstrapDialog`의 정보·확인·위험 변형으로 옮긴다. 취소 → 실행 순서, 오른쪽 정렬, 좁은 폭의 세로 배치, 가로 키보드 스크롤 규칙을 공유한다. 파일 선택기나 OS 권한창은 앱 팝업 통일 대상에서 제외한다.

완료 조건:

- 0건과 소량 검색 결과가 실제 완료 직후 표시된다.
- 삭제·완료·가져오기·내보내기 팝업의 여백과 액션 순서가 일치한다.
- 한·일 긴 문구, 320×568dp, 640×360dp+키보드 조건에서 모든 액션을 누를 수 있다.

### 3.6 PDF 페이지 구성과 앱 크기

차트 제목과 차트를 분리 불가능한 묶음으로 만들고, 데이터가 적을 때 빈 후속 페이지가 생기지 않도록 높이와 페이지 나눔을 조정한다. 한·일 글리프 전체를 보장하지 못하는 임의 서브셋으로 글꼴을 줄이지 않는다. 먼저 release APK/AAB의 실제 압축 크기와 Play 다운로드 영향을 측정한 뒤, 같은 글리프 범위를 유지하는 폰트 패키징 방법만 비교한다.

## 4. 권장 실행 단위

1. **파일 안전성:** B16 고유 파일명·원자적 쓰기와 B07 암호 UI 제거
2. **외부 보관:** B12 Android SAF 및 CSV/PDF 완료창 재설계
3. **튜토리얼 복구:** B13 저장소 표식 정리와 강제 종료 시나리오
4. **접근성:** B05 시스템바 정책과 B06 의미 레이블·터치 영역
5. **사용성:** B14 검색 지연 제거와 B15 공통 팝업 전환
6. **PDF 마감:** 페이지 묶음·빈 공간과 release 크기 최적화

각 단위는 관련 회귀 테스트, `flutter analyze`, 전체 `flutter test`, Android 빌드를 통과한 뒤 다음 단계로 이동한다. 파일·튜토리얼·시스템 UI 변경은 에뮬레이터만으로 닫지 않고 최소 1대의 실제 Android 기기 검증 결과를 남긴다.

## 2026-09-16 구현 반영

재조정 우선순위 1·2를 완료했다.

1. **PDF 파일 무결성·암호 UI 정리 완료:** 고유 파일명, 임시 파일 기록 후 최종 이동, 실패 시 기존 파일 보존을 구현했다. 지원하지 않는 암호 UI와 문서를 제거했다.
