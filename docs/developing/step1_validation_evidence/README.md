# 순서 1: 백업 검증·데이터 보호 검증

2026-09-15. 베타테스트 B02·B03 수정. 테스트 데이터는 전용 `ledger_beta_api36` / `emulator-5554`에만 사용했다. 기존 베타 보고서의 결함 증거는 변경하지 않았다.

- 수정 전 추가 회귀 검사에서 손상 파일·중복 ID 등 11개 실패를 확인하고 수정 후 통과했다.
- 구버전 v1/v2와 현재 v3의 왕복, 정상 빈 목록, 수입 중복/잘못된 ID, 중복 섹션, 헤더 유실, 잘린 인용, 존재하지 않는 날짜 등을 검사했다.
- SQLite에 저장 실패와 조용한 행 무시를 주입해 기존 4개 DB·설정 원문·활성 여행·튜토리얼 값 보존을 검사했다. 스냅샷 쓰기 실패, 복구 실패 후 재시도, ID 없는 수입의 개별 저장도 통과했다.
- 한·일, 320×568 논리 픽셀, 글자 배율 1.8에서 가져오기 건수 확인창의 확인/취소 조작을 검사했다.
- Android x86_64 debug APK 빌드 후 설치 성공. 빌드에는 기존 flutter_timezone/share_plus의 Kotlin 관련 경고가 있었으며 의존성을 변경하지 않았다.
- Android 파일 선택 → 검증 건수 표시 → 취소 → 재진입 → 승인 → 정상 복원을 실행했다. [확인창](android_import_preview.png), [성공 안내](android_import_success.png), [복원 DB](native_after_import.json).
- Android에서 복구본을 심고 앱을 강제 종료한 상태로 지출 DB를 제거해 부분 교체 중단 상태를 모의했다. 일반 앱 시작 경로로 복구한 뒤 모든 레코드가 원본과 같고 복구본이 제거됐음을 확인했다. [검증 결과](native_recovery_result.json), [복구 후 시작 화면](android_recovered_landing.png). 실제 import 진행 중 특정 명령 사이에서 프로세스를 종료한 시험이나 전원 차단 시험은 아니다.
- 실물 Android·저장 장치 고장·Web 브라우저에서의 수동 복구 시험은 수행하지 않았다. 현재 CSV의 온전한 행 단위 삭제 탐지 한계는 [저장 계약](../backup_restore_contract.md)에 명시했다.

전체 테스트와 정적 분석 결과는 같은 폴더의 `checks.txt`에 기록한다. `native_recovery_fixture.json`은 가상 데이터를 이용한 복구 시험 입력이다.

최종 결과: 전체 테스트 134개 통과·2개 제외. 이후 버전 누락 검증 1개를 추가해 파일 검증 13개를 별도로 재실행했고 모두 통과했다(전체 실행과 중복되는 항목을 합산하지 않음). 최종 `flutter analyze`는 문제 없음이며 한·일 언어팩은 각각 597개 키와 placeholder가 일치한다. 마지막 버전 검증 변경 후 Android APK도 다시 빌드·설치했다.
