## 1. 보고서 요약

핵심 작성·여행 관리·고정지출 복사·정상 백업 복원은 동작하지만, 데이터 복원 검증과 작은 화면의 입력 접근성을 먼저 보강해야 한다. 외형 통일 작업만으로는 이 문제들이 해결되지 않는다.

| 영역 | 확인 결과 | 프로젝트에 미치는 영향 |
|---|---|---|
| 데이터 보존 | 불완전한 CSV 수락, 중복 수입 ID 덮어쓰기 | 가져오기 과정에서 기록이 줄어들 수 있음 |
| 화면 적응 | 소비기록 최대 348px, 키보드가 열린 팝업 186px 넘침; 일본어 분석 화면도 넘침 | 목록·입력·확인 버튼에 접근하기 어려움 |
| PDF·파일 | 최초 오프라인 일본어 깨짐, 차트 비율 불일치, PDF 덮어쓰기, 암호·저장 문구 혼동 | 생성 결과와 보관 동작을 신뢰하기 어려움 |
| 사용성 | 상태바 대비, 이름 없는 버튼, 영어 요일, 팝업 불일치, 검색 지연 | 읽기·조작·접근성 저하 |
| 복구 내구성 | 튜토리얼 서비스 재생성 후 임시 데이터 잔존 | 실제 재시작 흐름의 추가 검증 필요 |

정상 확인: 고정지출의 0원 복사와 월별 안내 숨김, 여행 삭제 시 지출 금액을 보존한 평상시 전환, 여행 모드 버튼 변경, 배경 설정 유지, 정상 CSV 이사, PNG 생성, 지출 일괄 변경·삭제.

검사 규모는 Android 핵심 화면 캡처 28개와 별도 Widget 96개 조합이다. 전체 기존 테스트는 110개 통과·2개 제외, 정적 분석은 통과했다. Widget 탐색 검사의 성공 종료는 오류가 없다는 뜻이 아니다. 실물 기기, 예약 알림 실제 수신, 장기간 사용은 검증이 남아 있다. B02·B03·B13은 서비스/SQLite 재현이며 Android 전체 사용자 흐름으로 확인한 결함과 구분한다.

## 2. 우선순위와 작업 단위

## 3. 데이터와 파일 수정 지침

### 3.1 백업 형식과 기존 데이터 보호

- `data_im_export_service.dart`의 파싱·검증과 Provider의 교체 흐름을 구분한다. 파싱 결과를 검증된 복원 계획으로 만든 뒤에만 저장소를 변경한다.
- 버전별 필수 섹션·헤더·필드 규칙을 명시한다. 여행 기능 이전 백업에는 여행 정보가 없는 것을 허용하고, 명세상 존재해야 하는 현재 버전의 섹션 누락과 구분한다. 정상적인 빈 목록은 허용하되 헤더가 사라진 목록을 빈 데이터로 간주하지 않는다.
- 모든 데이터 종류의 ID 중복과 여행·태그 참조를 확인한다. 수입 ID도 같은 검증 경로에 포함한다. 구버전의 기본값은 문서화된 호환 변환에서만 부여한다.
- 기존 파일에 레코드 수나 본문 검증값이 없으면 완전한 행 단위 유실까지 검출할 수 없다. 새 형식에 섹션별 건수·본문 checksum을 도입한다면 버전을 올리고 구버전 읽기를 유지한다. checksum은 우발적 손상 탐지용이며 암호화·작성자 인증으로 설명하지 않는다. 기존 `signature` 역시 이메일/문자열 키 일치 확인이라는 계약을 유지한다.
- 복원 직전 종류별 건수와 전체 교체 대상(여행·설정 포함)을 보여준다. 취소하면 저장 작업을 시작하지 않는다.
- 지출·수입·고정지출·여행 DB와 SharedPreferences는 별도 저장소다. 개별 SQLite transaction만으로 전체 작업이 원자적이라고 판단하지 않는다. 교체 전에 복구 가능한 스냅샷과 작업 상태를 영속화하고, 중간 실패·재시작 시 일관된 이전 상태로 복구하는 절차를 별도 구현한다. 스냅샷 생성 실패 시 교체를 시작하지 않는다.
- 완료 안내 전에 종류별 건수·합계·참조와 설정 반영을 검증한다. 복구 정보는 성공 확정 후 정리하며 실제 데이터나 인증 문자열을 로그에 남기지 않는다.

필수 회귀 입력: 구버전 여행 없음, 현재 버전 여행·아이콘·배경 포함, 정상 0건, 섹션/헤더 누락, 중복 수입 ID, 잘못된 날짜·참조, 저장 도중 실패, 재시작 후 복구. 잘못된 파일은 실패 여부뿐 아니라 **기존 데이터가 그대로인지** 검사한다.

### 3.2 PDF와 보관 동작

- 배포 가능한 라이선스의 한·일 글꼴을 앱 자산에 포함하고 PDF 생성 서비스에서 읽는다. 최초 사용에 네트워크가 필요하지 않아야 한다. 글꼴 준비 실패는 명시적인 생성 실패로 처리하고 기존 파일은 보존한다.
- PDF 전용 렌더링과 금액 계산을 분리한다. 기본 수정안은 ‘일반 지출 카테고리’ 차트의 조각과 범례 모두 일반 지출 합계를 분모로 쓰고, 고정지출 포함 총액은 별도 요약으로 명시하는 것이다. 분모 0과 반올림 오차도 정의한다.
- PDF 암호화는 이번 결함 수정에서 새 기능으로 확대하지 않는다. 미지원 입력을 제거/비활성화하고 `README.md`·`README_JP.md`를 함께 정정한다.
- 파일명에는 생성 시각과 충돌 회피 식별자를 붙인다. 임시 파일에 생성이 끝난 뒤 최종 파일로 공개하고, 생성 실패로 이전 보고서를 훼손하지 않는다.
- ‘파일로 저장’은 사용자가 목적지를 고르고 실제 쓰기 성공까지 확인하는 동작으로 정의한다. ‘공유’는 OS 공유창, ‘완료’는 창 닫기로 구분한다. Android 목적지 선택은 Storage Access Framework를 사용하되 현재 Flutter 플러그인의 Android 지원 여부를 먼저 확인한다. [Android 파일 접근 안내](https://developer.android.com/guide/topics/providers/document-provider).
- PDF 제목과 그래프를 같은 페이지에 묶고, 적은 데이터에서 불필요한 빈 페이지를 줄인다. 모든 페이지를 렌더링해 검수하며 텍스트 추출 성공만으로 글꼴 정상 판정을 하지 않는다.

## 4. 멀티 디바이스 UI의 공통 원칙

통일할 대상은 **색상·글꼴 역할·여백 체계·정보 순서·행동 의미**다. 화면 폭이 달라지면 열 수·줄바꿈·탐색 배치는 달라져도 된다. 휴대전화와 태블릿별로 페이지 구현을 복제하면 수정과 디자인이 갈라지므로, 같은 상태·컴포넌트에 배치만 다르게 적용한다.

기기 모델이나 물리 픽셀로 분기하지 않는다. 전체 창은 `MediaQuery.sizeOf`, 카드·팝업 등 해당 영역은 `LayoutBuilder`의 가용 제약으로 판단한다. 이는 분할 화면에서도 적용된다. [Flutter 적응형 UI 안내](https://docs.flutter.dev/ui/adaptive-responsive/general).

### 4.1 초기 레이아웃 정책

아래 수치는 이 프로젝트에 제안하는 시작값이다. 기존 구현값이나 모든 디바이스에 적용되는 절대 기준은 아니다. 회귀 화면을 검토해 조정하고 한 곳에서 관리한다.

| 가용 본문 폭 | 기본 배치 | 적용 규칙 |
|---|---|---|
| 600dp 미만 | 한 열, 하단 탐색 | 폼·기록·요약 순서 유지. 긴 제어부는 다음 줄로 이동 |
| 600~839dp | 넓은 한 열 우선 | 충분한 높이·최소 열 폭이 확보된 카드 그룹만 두 열 허용 |
| 840dp 이상 | 요약/목록 또는 목록/상세 두 영역 | 전체 본문 최대 폭 1200dp 제안. 입력 폼은 최대 600dp로 제한 |
| 폭과 무관하게 높이가 부족함 | 세로 스크롤 우선 | 640×360 가로 화면에 태블릿 배치를 강제로 적용하지 않음 |

탐색을 Rail로 바꾸는 작업은 초기 넘침 수정과 분리한다. 도입 시 같은 목적지 목록·아이콘·레이블을 공유하고, 너비 변경 후 선택 탭·선택 월·입력값·스크롤 위치를 유지한다. 단순 회전은 새 화면 진입이 아니므로 고정지출 안내 팝업을 중복 표시하지 않는다.

### 4.2 스타일 기준을 한 곳에서 관리

`main.dart`의 테마와 `bootstrap_style`의 현재 색상·여백을 먼저 목록화한다. 기존 디자인에서 값을 추출해 공통 테마로 옮기고, 신규 디자인을 페이지마다 따로 만들지 않는다.

| 항목 | 통일 지침 |
|---|---|
| 여백 | 4·8·12·16·24·32dp 단계 사용. 기본 페이지 좌우 16dp, 넓은 화면 24dp 제안 |
| 모서리·테두리·그림자 | 카드·입력·팝업의 기존 대표 스타일을 토큰화. 임의의 반경·그림자 추가 금지 |
| 글자 | `TextTheme`의 제목·본문·보조 역할 사용. 기기 폭에 비례해 전체 글꼴 크기를 곱하지 않음 |
| 색상 | 표면·본문·보조·일반 액션·여행 액션·위험 액션의 의미로 관리 |
| 버튼 | 최소 터치 영역 48×48dp. 글자 확대 시 높이 증가 허용. 아이콘이 작아도 터치 영역 유지 |
| 간격 예외 | 디자인 토큰으로 표현할 수 없는 기능상 이유가 있을 때만 페이지 전용 값 허용 |

일반 본문·주요 조작은 배경 대비 4.5:1을 프로젝트 검수 목표로 잡고, TalkBack 및 큰 글자 조작을 함께 확인한다. [Flutter 접근성 안내](https://docs.flutter.dev/ui/accessibility).

### 4.3 화면 유형별 구현 규칙

**소비기록·목록:** 달력+기록에 하나의 주 스크롤 흐름을 둔다. 큰 목록은 지연 렌더링하고, 무조건적인 중첩 스크롤과 전체 `shrinkWrap`으로 문제를 우회하지 않는다. 달력 접기 기능을 제공하되 날짜 선택·선택 월을 보존한다. 하단 기록 버튼이 가리는 만큼 마지막 목록 항목에 여유 공간을 둔다. 5주/6주 달력과 큰 글자 모두 검사한다.

**기간 선택·필터:** 기간 유형, 이전/다음, 현재 기간을 하나의 고정 `Row`에 모두 강제하지 않는다. 공간 부족 시 유형과 날짜 탐색을 두 줄로 나눈다. 날짜·금액·주요 행동은 잘라서 숨기지 않는다. 여행명·메모처럼 긴 보조 내용은 줄바꿈하고 필요하면 상세에서 전체를 제공한다.

**팝업·입력 시트:** 공통 팝업의 기본 최대 폭은 기존 440dp를 유지하는 것으로 시작한다. 실제 높이는 키보드와 안전 영역을 제외한 제약 안에 둔다. 본문은 스크롤하고 액션은 접근 가능한 영역에 배치한다. 제목·액션만으로 공간이 부족하면 전체 스크롤 또는 전체 화면 입력으로 전환한다. `SafeArea`와 `viewInsets` 처리는 한 계층이 책임지고 Scaffold/기본 Dialog가 이미 처리한 키보드 높이를 다시 빼지 않는다. Flutter도 긴 Dialog 본문의 스크롤 처리를 명시한다. [AlertDialog 문서](https://api.flutter.dev/flutter/material/AlertDialog-class.html).

**팝업 통일:** 확인·경고·완료는 같은 외곽·여백·본문 폭·액션 규칙을 쓰고 의미별 아이콘·색상만 다르게 한다. 한·일 가로 액션은 ‘취소 → 실행’ 순서로 오른쪽 정렬한다. 폭이 부족하면 같은 읽기 순서로 세로 배치하며 버튼 글자는 축소하지 않는다. 삭제는 ‘확인’보다 ‘여행 삭제’처럼 결과를 나타내는 문구를 쓴다. 월별 숨김 체크박스와 취소/확인 의미는 기존 동작을 보존한다.

**배경·전환:** 기존 루트 `AppBackground`와 시작 설정 로딩을 유지한다. 각 페이지에 새 그라데이션을 생성하지 않는다. `app_page_transitions.dart`의 투명 전환 배경 계약을 보존하며, 페이지 본문이 기본 불투명 색으로 루트 배경을 가리지 않게 한다. 여행 모드는 배경 선택과 분리하고 초록색 버튼·여행 문구를 함께 사용한다. 상태바 아이콘은 각 팔레트의 가장 밝은 프레임에서도 읽히도록 정하고 필요하면 시스템바 영역에 안정적인 표면을 둔다.

**현지화·접근성:** 앱 저장 locale `jp`와 Flutter `ja` 변환을 유지한다. 요일은 locale에 맞는 짧은 이름을 사용한다. 시스템 글자 확대를 전역 차단하거나 `FittedBox`로 주요 글자를 축소하지 않는다. 최신 `TextScaler` 흐름을 따르고 글자 배율을 고정 숫자로 환산한 높이 계산에 의존하지 않는다. 아이콘 전용 버튼에는 동작·대상을 알 수 있는 의미 이름을 넣되 레이블이 중복 낭독되지 않게 검사한다. 카테고리는 저장된 안정적인 아이콘 식별자와 레이블을 함께 표시하고, 알 수 없는 아이콘에는 기본 아이콘을 사용한다.

## 6. 회귀 검사와 완료 기준

### 화면 검사 행렬

| 조건 | 필수 검사 |
|---|---|
| 320×568, 393×852 | 한·일, 기본 글자, 핵심 5탭 및 변경한 화면 |
| 360×640 | 한·일 글자 1.8 및 OS 최대 글자 설정, 긴 이름·큰 금액 |
| 640×360 | 키보드 표시/숨김, 태그·지출·여행 입력, 확인창 |
| 800×1280 | 카드 폭·정렬·터치 영역, 한 열과 두 영역 배치 |
| 599/600, 839/840dp 경계 | 전환 직전·직후의 넘침 및 상태 보존 |
| 실행 중 창 크기 변경 | 분할 화면·회전, 작성 중 값·선택 월·스크롤 유지 |

위 행렬은 앞으로의 완료 조건이며 모두 이미 검사했다는 뜻은 아니다. 각 조건에서 빈 데이터, 로딩, 오류, 긴 한·일 문구를 포함한다. 배경은 단색+4개 그라데이션, 일반/여행 모드를 대표 화면에서 교차 검사한다.

- 탐색 스크립트에서 재현한 핵심 결함은 `test/`의 실패하는 회귀 테스트로 옮긴 뒤 수정한다. Flutter 오류를 수집만 하는 감사 스크립트를 CI 합격 기준으로 사용하지 않는다.
- Widget 테스트는 넘침 부재 외에 마지막 항목·확인 버튼으로 스크롤해 실제 탭할 수 있는지 확인한다. 골든 이미지는 같은 Flutter·폰트·플랫폼 조건에서 비교하며 Android 실기 검사를 대체하지 않는다.
- 배경 전환은 완료 후뿐 아니라 시작·중간·끝 프레임을 확인한다. cold start, 우측 사이드바 이동, 뒤로 가기도 포함한다.
- 수정한 Dart 포맷 → 관련 테스트 → `flutter analyze` 순서로 실행한다. 공통 모델·Provider·저장소·현지화 변경 시 전체 `flutter test`를 실행한다.
- DB·파일·알림 변경은 Android 실행 검증을 추가한다. 최소한 작은 실물 Android 폰과 큰 화면 기기에서 핵심 흐름을 확인하고, 기본 렌더러·지원 최소 OS·목표 OS의 차이를 기록한다. 미보유 조건은 미검증으로 남긴다.
- PR에는 관련 B 번호, 재현 입력, 변경 전후 같은 조건의 캡처, 테스트 결과, 남은 제한을 적는다. UI가 바뀌었다는 이유만으로 모든 골든을 일괄 승인하지 않는다.
